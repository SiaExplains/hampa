# i18n — Persian first, three locales

## Locales

| Code | Language | Direction | Default |
|---|---|---|---|
| `fa` | Persian (Farsi) | RTL | **yes** |
| `en` | English | LTR | |
| `de` | German | LTR | |

## Routing

- `next-intl` with `[locale]` segment: `/fa/...`, `/en/...`, `/de/...`. `localePrefix: 'always'` — no prefix-less URLs, so links are unambiguous when shared in Telegram.
- Locale resolution order: URL → `users.locale` (logged in) → `NEXT_LOCALE` cookie → `Accept-Language` → `fa`.
- Changing locale in settings updates `users.locale` and redirects to the same path under the new prefix.
- Emails and push use `users.locale`. Invite landing page uses the inviter's locale as initial guess, with a visible switch.

## RTL

- `<html lang dir>` set in the root layout from the locale. Every layout must work in both directions — **test every screen in `fa` first.**
- Tailwind: use logical utilities only (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`, `text-start`). `ml/mr/pl/pr/left/right` are banned by an ESLint rule (`eslint-plugin-tailwindcss` + a custom rule or a lint grep in CI).
- Icons that imply direction (arrows, chevrons, "back") get `rtl:rotate-180` or a mirrored variant.
- shadcn components: verify Sheet, Dropdown, Toast and Dialog positions in RTL; patch with `dir` props where Radix supports them.

## Numbers, dates, times

- Persian UI shows **Persian digits** (`۰۱۲۳۴۵۶۷۸۹`) via the Vazirmatn Farsi-Digits build for `fa` text (glyph-only: the characters stay Latin), and `Intl.NumberFormat('fa-IR')` for formatted numbers. Inputs stay Latin digits (server receives Latin).
- Calendar: **Gregorian for all locales** in Phase 1 (events are scheduled in Berlin, members live Gregorian lives). Persian weekday/month names via `Intl.DateTimeFormat('fa-IR', { calendar: 'gregory' })`. A Jalali toggle is a later nicety.
- Times always rendered in `Europe/Berlin` regardless of device timezone (the event is in Berlin), with the zone shown once on the event page.
- Week starts Monday in all locales (streak logic and calendar widgets agree).

## Message files

`src/i18n/messages/{fa,en,de}.json`, namespaced by feature (`events.register`, `profile.level`). ICU plurals for counts (`{count, plural, one {# member} other {# members}}`). Persian plural rule: `one`/`other`.

Workflow: write `en` first as the canonical key set, then `fa` and `de`. A CI check fails on missing keys in any locale (`scripts/check-i18n.ts`, runs in the same CI job).

Tone per locale: fa — warm, informal "شما"-free where natural, like the Telegram group; de — "du"; en — plain and friendly.

## User-generated content

Event titles/descriptions, bios, sport descriptions written by coaches are stored as typed — **no machine translation**. Sport names and tier names are translated (columns per locale / message keys).

## Fonts

- Vazirmatn (OFL) for `fa`, Inter (OFL) for `en`/`de`, both self-hosted, weights 400/500/600/700, `display: swap`. Font is selected by `html[lang]` in CSS, not per component.

## Definition of done for any UI change

Screenshot or manual check in `fa` at 375px **and** one LTR locale. A layout that passes only in English is not done.
